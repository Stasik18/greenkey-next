# Миграция GreenKey на Next.js

## Текущий результат

Исходный сайт на HTML/CSS/JavaScript перенесён в Next.js App Router, React, TypeScript и Tailwind CSS.

### Маршруты

- `/` - главная страница со всеми секциями оригинала.
- `/calculator` - подробный калькулятор комплектаций, 18 групп опций, расчёт стоимости и форма.
- `/gallery` - объекты, этапы строительства, просмотр фотографий и лайтбокс.
- `/privacy` - политика конфиденциальности.
- `not-found` - собственная страница 404.

Старые адреса `/index.html`, `/calculator.html`, `/gallery.html` и `/privacy.html` перенаправляются на новые маршруты постоянным redirect 308.

### Главная страница

- Секции вынесены в отдельные React-компоненты.
- Основная стилизация выполнена Tailwind CSS. В `home.css` оставлены keyframes, анимационные состояния и несколько специальных селекторов.
- Калькуляторы каркасного дома, ремонта и дизайн-проекта управляются React state через `PriceCalculator`.
- `ContactsLeadForm` управляет вкладками формы через React state.
- Общий `LeadForm` обрабатывает клиентскую проверку, UTM-метки, отправку, статусы и запасные каналы связи.
- `HomeDialogs` управляет модальными окнами, inert-фоном, фокусом, Escape и блокировкой прокрутки.
- `CallButton` возвращает общую плавающую кнопку звонка; она исчезает при появлении Footer и учитывает нижнюю панель калькулятора.
- Галерея поддерживает deep link на объект, вложенный lightbox со стрелками/свайпом, форму `gallery-call` и управление верхним модальным слоем.
- `HomePageEffects` отвечает за видео, частицы, typewriter, reveal, счётчики, индикатор прокрутки, pointer effects и preloader.
- `BuildSection` управляет SVG fallback и этапами строительства.

### Декомпозиция страниц

Все страницы разложены по самостоятельным UI-компонентам, а состояние и вычисления вынесены из крупных компонентов:

- Калькулятор: `CalculatorPage` собирает `CalculatorHeader`, `BaseConfiguration`, `OptionsGroup`, `CalculatorSummary`, `CalculatorLeadSection` и `CalculatorMobileBar`. Вариант опции, группа, summary и форма имеют отдельные компоненты. Расчёты вынесены в `lib/calculator.ts`, состояние - в `lib/useCalculator.ts`.
- Галерея: `GalleryPage` - серверная композиция. Карточки объектов, viewer, hero viewer, факты дома, проектная галерея, таймлайн, отдельный этап, CTA, lightbox и форма заявки разделены. Состояние вынесено в `useGalleryController`, keyboard, focus/inert и swipe - в отдельные хуки.
- Политика: `PrivacyPage` собирает четыре смысловые группы из 13 разделов, текст разделов находится в отдельных компонентах.
- Главная: каждая секция имеет свой компонент; `BuildSection` использует отдельный SVG scene renderer, эффекты разнесены по модулям, модальная разметка отделена от управления состоянием, калькулятор главной разделён на tabs, area, result и individual offer.

В результате ни один компонент страницы не содержит сотни строк несвязанной разметки и логики. Большие файлы данных/геометрии остаются отдельными модулями, а не React-компонентами.

### Калькулятор и галерея

- Стили калькулятора и галереи вынесены из общего `globals.css` в отдельные `calculator.css` и `gallery.css`; они подключаются только на своих маршрутах.
- Общие глобальные стили содержат только reset, базовую типографику и дизайн-токены.
- Страницы используют те же семейства шрифтов, что и оригинал: Inter для основного текста и Montserrat для заголовков. Файлы шрифтов собираются через `next/font`, поэтому браузеру не требуется обращаться к Google Fonts во время работы сайта.
- `GalleryPage` остаётся Server Component. Статические заголовок и пояснение также серверные; клиентская логика карточек, просмотра объекта, лайтбокса и формы изолирована в `GalleryInteractive`.
- Данные объектов и этапов, функции подсчёта и построения путей к фотографиям вынесены из UI-компонентов в `model/gallery-data.ts` и `lib/gallery-utils.ts`.
- Просмотр объекта, карточки, лайтбокс и форма заявки разделены на небольшие компоненты.
- Фотографии галереи уже оптимизированы в WebP и имеют отдельные миниатюры. Они отдаются напрямую без повторной обработки Next Image; на первоначальной загрузке страницы запрашиваются только две обложки объектов, фотографии этапов подгружаются лениво при открытии объекта и прокрутке.
- Этапы таймлайна используют `content-visibility: auto`, чтобы браузер не тратил ресурсы на отрисовку длинного содержимого за пределами экрана.

### Иконка сайта

`app/icon.svg` - специальный файл App Router. Next.js автоматически использует его как favicon и генерирует маршрут `/icon.svg`; это не React-компонент и не случайно оставленный файл.

### JavaScript и 3D

Старые `home-interactions.js` и `lead-form.js` удалены. Их поведение перенесено в React + TypeScript. В `src/` и `app/` нет прикладных `.js` / `.jsx` файлов.

В `public/assets/js/build3d/` оставлен специализированный 3D-движок. Он использует Three.js и GSAP, загружается лениво рядом с секцией строительства и забирает её после готовности первого кадра. Это изолированный графический движок, а не старая система интерактивности сайта. Его внутренние модули можно типизировать отдельно, не переписывая саму сцену на React.

### Архитектура

- `app/` отвечает за маршруты, metadata, redirect и API.
- `src/pages/` содержит страницы и их секции.
- `src/shared/ui/` содержит UI Kit и общие компоненты.
- `src/shared/lib/hooks/` содержит переиспользуемые хуки.
- `src/widgets/` содержит Header, Footer и CallButton.
- `src/docs/architecture.md` описывает структуру и правила проектирования.

Header использует `usePathname` для разрешения якорей. На главной `#about` остаётся якорем текущей страницы, на внутренних страницах превращается в `/#about`.

### SEO и безопасность

- Перенесены metadata, canonical URL и Open Graph.
- Добавлены JSON-LD `GeneralContractor` и `BreadcrumbList`.
- Добавлены `app/robots.ts` и `app/sitemap.ts`.
- Перенесены основные security headers из Apache-конфигурации в `next.config.ts`.
- Настроено кэширование публичных assets и vendor-библиотек.

## Ограничения и незавершённые интеграции

### Отправка заявок

Логика исходного `api/send-lead.php` перенесена в TypeScript: проверки Origin и размера тела, honeypot, проверка времени заполнения, белый список форм, очистка данных, UTM, rate limit, дедупликация с состояниями pending/sent, журналирование и формирование письма. SMTP-транспорт использует TLS 1.2+ и проверку сертификата. Приём заявок по умолчанию выключен (`GREENKEY_LEAD_ENABLED=false`), поэтому API честно возвращает `503 disabled`. Настройки перечислены в `.env.example`; пароль SMTP задаётся только в окружении сервера.

### Деплой

Для локальной настройки скопируй `.env.example` в `.env.local`. В production SMTP-секреты задаются в окружении Node-процесса, а не в репозитории. При serverless или нескольких Node-инстансах локальное файловое хранилище лимитов нужно заменить общим Redis/DB. `GREENKEY_TRUST_PROXY=true` включается только при доверенном reverse proxy, который перезаписывает IP-заголовки.

Правила принудительного HTTPS и `www` -> без `www` зависят от прокси/хостинга. В исходной Apache-конфигурации отдельно описан нюанс `X-Forwarded-Proto`; эти правила нужно настроить на уровне реального хостинга, не создавая redirect loop.

## Проверки последнего этапа

- TypeScript: `tsc --noEmit` - успешно.
- ESLint: `eslint .` - успешно; статические файлы в `public/` исключены из lint.
- Production build: `next build` - успешно.
- Smoke test: `/`, `/calculator`, `/gallery`, `/privacy`, `/robots.txt`, `/sitemap.xml` возвращают 200.
- Неизвестный маршрут возвращает 404.
- Старые `.html` маршруты возвращают 308 на новые URL.
- На `/calculator` Header отдаёт ссылки `/#about`, а не `#about`.
- `/api/send-lead` возвращает ожидаемый `503 disabled`.
- Backend проверен с тестовым TLS SMTP-сервером: письмо принято, повторная заявка распознана как duplicate и повторно не отправлена. При недоступном SMTP API возвращает 502, не создавая ложного успеха.
